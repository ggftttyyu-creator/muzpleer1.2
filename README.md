# 🎧 MuzPlayer

Мультипровайдерный музыкальный плеер: один интерфейс — шесть источников.
Каждый сервис подключается как **плагин-адаптер**, поэтому плеер не знает и не должен знать,
Audius у тебя играет, Яндекс.Музыку или живое радио.

**Работает:** **шесть тем оформления** (четыре тёмные и две светлые, с переключением в один клик),
веерный поиск по всем источникам, очередь, перемотка, **три режима перемешивания
(в том числе умное, по вкусу)**, повтор, избранное, интерфейс на русском, MediaSession,
визуализатор на WebAudio, вход в Яндекс.Музыку по коду и воспроизведение оттуда в 320 kbps,
**караоке с синхронным текстом**, **вкладка «Для вас» с рекомендациями по реально прослушанному
и автоподбором в конце очереди**, а все ключи и аккаунты вынесены в отдельную вкладку **«Настройки»**.

## ⚡ Быстрый старт

```bash
cd muzplayer
npm start          # зависимостей НЕТ — только node >= 20
# → http://localhost:4173

npm test           # модульные тесты логики: рандом, вкусы, рекомендации, устойчивость прокси
npm run smoke      # (в другом терминале) смоук-тест интерфейса: 72 проверки
npm run layout     # проверка раскладки в настоящем браузере: прокрутка всех панелей
npm run lyrics     # живая проверка караоке: трек играет сам, подсветка должна ехать сама
npm run rec        # живая проверка рандома и рекомендаций на настоящих треках (~45 сек)
npm run themes     # проверка тем в браузере: контраст, применение, сохранение выбора
npm run shots      # скриншоты всех тем в папку shots/ — посмотреть глазами
```

Проверки делятся на два сорта. `npm test` — быстрые модульные (не нужен ни сервер, ни браузер).
Остальные четыре — «живые»: поднимают настоящий браузер, играют настоящие треки и смотрят, что
происходит на самом деле. Именно они ловят то, чего не видно в заглушках: зависшую подсветку
караоке, обрезанную прокрутку, отвалившийся автоподбор.

Сервер поднимает и API-прокси, и раздачу фронтенда. Чистый `index.html` без сервера не заработает:
он не сможет ни обойти CORS, ни спрятать токены, ни проксировать аудио с перемоткой.

**Хоткеи:** `Space` — play/pause · `←/→` — ±5 сек · `Shift+←/→` — трек · `↑/↓` — громкость ·
`M` — mute · `S` — shuffle · `R` — repeat · `Q` — очередь · `L` — текст · **`T` — тема** ·
`/` — поиск · `Esc` — закрыть.

## 🔌 Карта API: что реально подключается (проверено вживую, сентябрь 2026)

| Сервис | Офиц. API | Ключ | Звук в браузере | Итог |
|---|---|---|---|---|
| **Audius** | ✅ публичное | не нужен | ✅ **полные треки** | 🟢 работает из коробки |
| **Radio-Browser** | ✅ открытое | не нужен | ✅ **живые потоки** | 🟢 50 000+ станций |
| **Яндекс.Музыка** | ❌ отсутствует | токен юзера | ✅ **полный mp3, 320 kbps** | 🟢 включается входом по коду |
| **Deezer** | ✅ публичное | не нужен | ⚠️ только 30 сек | 🟡 каталог, метаданные, превью |
| **iTunes / Apple** | ✅ публичное | не нужен | ⚠️ только 30 сек | 🟡 лучшие обложки 600px |
| **YouTube / YT Music** | ✅ Data API v3 | ключ Google | ⚠️ только iframe-плеер | 🟠 своя вкладка + квота |
| **Spotify** | ✅ публичное | OAuth | ❌ нельзя | 🔴 `preview_url` удалён, SDK требует Premium |
| **VK Музыка** | ❌ закрыт навсегда | — | ❌ | 🔴 публичный audio API отключён **16.12.2016** |

### 🟢 Полноценное воспроизведение

**Audius** — `api.audius.co`, отдаёт **полные mp3**. У треков есть флаг `is_streamable`;
при `false` эндпоинт `/stream` возвращает 404, поэтому такие треки отфильтровываются
на стороне провайдера, чтобы не рвать очередь.

**Radio-Browser** — открытая база интернет-радио, `url_resolved` — прямой поток MP3/AAC.
Перемотки нет по определению (живой эфир).

**Яндекс.Музыка** — см. отдельный раздел ниже. **Играет полные треки в 320 kbps с перемоткой.**

### 🟡 Только 30-секундные превью

**Deezer** (`api.deezer.com`, без ключа, CORS открыт) и **iTunes Search API**
(`itunes.apple.com/search`). Отдают `preview` / `previewUrl` — 30-сек mp3.

У iTunes поле `artworkUrl100` апскейлится до `600x600` простой заменой в URL.
Ещё нюанс: превью приходят с `Content-Type: audio/x-m4p` (лейбл DRM-формата, хотя внутри
обычный AAC) — прокси нормализует его в `audio/mp4`, иначе браузеры капризничают.

## 🟡 Яндекс.Музыка: как это работает

Официального API для сторонних разработчиков у Яндекса **нет** — ни публичного, ни
партнёрского для музыки. Используется неофициальный реверс-инжинирный API
(как в библиотеке [MarshalX/yandex-music-api](https://github.com/MarshalX/yandex-music-api)).
**Это серая зона: работает, но нарушает пользовательское соглашение сервиса и может сломаться.**

### Вход — OAuth Device Flow

Пароль приложению не передаётся: сервер просит код у `oauth.yandex.ru/device/code`,
вы показываете его на `ya.ru/device` и подтверждаете вход у Яндекса. Токен сохраняется
локально в `.yandex-auth.json` (в `.gitignore`) и уходит только на `*.yandex.net`.

Дальше доступны: **поиск**, **«Мне нравится»**, обложки и **воспроизведение**.

### Воспроизведение: AES-расшифровки НЕ нужно

Во всех старых гайдах написано, что Яндекс отдаёт mp3 в AES-зашифрованном виде и нужен
`key` из `download-info`. **Это устарело.** Проверено вживую: цепочка отдаёт обычный mp3.

```
GET /tracks/{id}/download-info?can_use_download_info=1
      → подписанный downloadInfoUrl (codec: mp3, bitrateInKbps: 320)
GET {downloadInfoUrl}                         → XML: host, path, ts, s
GET https://{host}/get-mp3/{s}/{ts}{path}     → обычный mp3, HTTP 200/206
```

Что важно на практике:
- поля `key` в ответе **нет** — расшифровывать нечего;
- подписанная ссылка `/get-mp3/...` работает **без токена**, обычным GET;
- она поддерживает **Range** → перемотка работает (`206 Partial Content`);
- ссылка подписанная и временная, поэтому резолв кэшируется всего на 2 минуты.

### Грабли: антибот Яндекса и Node

Самое неочевидное место всего проекта. С одинаковыми заголовками:

| Клиент | Ответ |
|---|---|
| `curl` | ✅ 200 |
| Python `urllib` | ✅ 200 |
| Node `fetch` (undici) | ❌ 403 + HTML-страница |
| Node `http2` | ❌ 403 |
| Node `node:https` | ✅ 200 |

То есть край Яндекса фильтрует по TLS/HTTP-фингерпринту, и Node-fetch в чёрном списке.
Поэтому **все** запросы к `*.yandex.net` в проекте идут через нативный `node:https`:
и API (`src/providers/yandex.js`), и аудио-поток, и обложки (`src/util.js`,
функция `needsNativeTransport`). Если однажды покажется, что «можно упростить на fetch» —
нельзя, вернётся 403.

Ещё один нюанс: обложки приходят как `avatars.yandex.net/get-music-content/…/%%` —
**без схемы**, и с `%%` вместо размера. Если не доставить `https://`, прокси картинок
справедливо отвергнет такой URL как подозрительный.

## 🟠 YouTube: почему отдельный режим

**Воспроизведения через API не существует** — Google не отдаёт аудиопоток. Единственный
легальный путь — встроенный IFrame Player, то есть видео с рекламой внутри страницы.
Поэтому YouTube — не `<audio>`, а отдельный док с `<iframe>`: у него своя логика
прогресса (опрос `getCurrentTime`), своя громкость (`setVolume`) и своя перемотка (`seekTo`).
Плеер сам переключается между режимами `audio` и `yt`, а очередь, MediaSession и хоткеи общие.

**Квота YouTube Data API v3** — 10 000 units в день:

| Операция | Стоимость | Сколько влезет |
|---|---|---|
| `search.list` (поиск) | 100 units | ~100 поисков |
| `videos.list` (детали, длительность) | 1 unit | 10 000 |
| `videos.list` c `chart=mostPopular` (чарт) | 1 unit | 10 000 |

Поэтому: поиск кэшируется на 10 минут, а на главной показывается **чарт за 1 unit**.
Счётчик квоты виден в сайдбаре, сброс — в полночь по Тихоокеанскому времени.

**Ключ не нужен, чтобы слушать по ссылке.** Вставьте ссылку YouTube в строку поиска и
нажмите Enter — IFrame-плеер играет по ID напрямую; название и автор подтянутся из самого
плеера. Ключ нужен только для поиска и метаданных.

## 🎨 Темы оформления

Шесть готовых тем — четыре тёмные и две светлые. Переключаются тремя способами:
значок палитры у строки поиска (быстрое окно), карточки в **Настройки → Оформление**
и клавиша **T** (по кругу). Выбор запоминается и подставляется ещё **до первой
отрисовки** страницы, поэтому при запуске не мелькает чужая палитра.

| Тема | Настроение | Кому |
|---|---|---|
| **Аврора** (по умолчанию) | глубокая ночь, фиолет и циан | универсальная тёмная |
| **Неон** | циберпанк, кислотно-розовый и мятный | погромче и поярче |
| **Закат** | тёплая ночь, янтарь и роза | уютная тёмная |
| **Графит** | монохром без цвета | «ничего лишнего» |
| **День** | светлая, нейтральная, индиго | яркий свет, работа днём |
| **Бумага** | светлая, тёплая, тёмно-зелёная с янтарём | чтение, вечернее освещение |

### Как это устроено

Вся палитра — это переменные CSS в `public/styles.css`, а тема — один блок
`:root[data-theme="…"]` со своим набором. В правилах **не осталось ни одного
жёстко зашитого цвета** (кроме белого, чёрного и красного бренда YouTube), поэтому
новый элемент интерфейса автоматически выглядит правильно во всех темах, а новая
тема — это 30 строк переменных. Прозрачные слои берутся из `--tint` (в тёмных
темах он белый, в светлых — чёрный), от этого списки, карточки и панели корректно
работают и на светлом фоне.

За это следят три уровня проверок:

- `npm test` — 9 тестов: у каждой темы полный набор переменных, читаемый контраст
  по WCAG, отсутствие «забытых» цветов в правилах, образцы в интерфейсе совпадают
  с палитрой, переключение по кругу, мусор в настройках не ломает вид;
- `npm run smoke` — 13 проверок в интерфейсе: карточки есть, выбор применяется и
  сохраняется, клавиша T работает, Esc закрывает окно, несуществующая тема
  откатывается к запасной;
- `npm run themes` — настоящий браузер сам считает итоговые цвета: контраст всех
  пар, режим системных элементов (`color-scheme`) и то, что сохранённая тема
  применяется после перезагрузки.

Посмотреть все темы сразу: `npm run shots` — складывает PNG в `shots/`.

## 🎲 Рандом и рекомендации

Перемешивание и подбор — не украшение, а алгоритмы, и у них есть проверяемое поведение:
в тестах крутится статистика (хи-квадрат на равномерность), а `npm run rec` гоняет
настоящие треки в браузере.

### Три режима перемешивания (кнопка в плеере или клавиша `S`)

| Режим | Что делает | Зачем |
|---|---|---|
| **выкл** | строгий порядок очереди | обычное поведение |
| **рандом** | `ShuffleBag`: трек не повторится, пока не прозвучат все | лечит главную беду случайного выбора — «одни и те же три песни» |
| **умное** | `WeightedBag`: вес зависит от вкуса | любимые исполнители выпадают чаще, но не затирают остальных |

Внутри — честная случайность (перестановка Кнута над индексной перестановкой), а не
«почти случайная» сортировка: за цикл каждый трек звучит ровно один раз. Индикатор в
панели очереди честно показывает состояние мешка: *«Рандом без повторов · в мешке 7 из 12»*.

### Профиль вкусов

Плеер запоминает прослушивания и пропуски: трек засчитывается прослушанным, если прозвучало
`min(20 сек, max(8 сек, 30% длительности))` — раньше этого срока уход вперёд считается
**пропуском** (это можно выключить в настройках). Каждое событие имеет вес по свежести:
полураспад **14 дней**, старые записи тихо перестают влиять. Профиль виден во вкладке
**«Для вас»**: сколько прослушано, сколько пропущено, любимые исполнители.

### Как собирается подборка

```
итоговый вес = 0.50 × похожесть + 0.34 × привязанность к артисту + 0.16 × новизна (+ шум 0.06)
```

- **похожесть** — насколько кандидат близок к тому, что реально слушали (сравнение артиста, названия и жанров);
- **привязанность** — сколько раз и как давно слушали этого исполнителя;
- **новизна** — то, что ещё не слушали, получает бонус: иначе подборка замыкается на трёх песнях;
- **шум** — маленькая случайность, чтобы подборка каждый раз была другой;
- **лимит два трека подряд от одного артиста** — разнообразие важнее арифметики.

Из этого работают: вкладка **«Для вас»** (подборка + «Продолжить слушать» + кнопки любимых
исполнителей), **автоподбор в конце очереди** (когда треки кончились, очередь дополняется
похожим, а не молчит) и кнопки настройки в «Настройках» → **«Вкусы и рекомендации»**
(автоподбор вкл/выкл, считать пропуски, «открыть мои вкусы», «забыть историю»).

Вся логика — в `public/rec.js`: один модуль без DOM и сети, поэтому его можно честно тестировать.

## 🧯 Если что-то не работает

| Симптом | Причина и лечение |
|---|---|
| Экран «🧩 Интерфейс не запустился» | Сценарий `app.js` не загрузился: чаще всего браузер взял старую копию из кэша. **Ctrl + Shift + R**. Если вы во встроенном превью — откройте **http://localhost:4173** в обычной вкладке. |
| Пустая тёмная страница, ничего не нажимается | Раньше так выглядел незапустившийся плеер. Теперь вместо пустоты всегда виден диагноз: «не запустился» (сбой сценария), «не отвечает» (нет сервера) или «Плеер не запустился» с текстом ошибки и штампом сборки. |
| Экран «🔌 Сервер MuzPlayer не отвечает» | Сервер не запущен. `npm start` в папке проекта → **http://localhost:4173**. Открывать `public/index.html` двойным щелчком бесполезно: ES-модули и API работают только через сервер. Когда сервер вернётся, интерфейс оживёт сам — перезагружать не нужно. |
| Интерфейс выглядит старым: нет вкладки «Настройки», караоке | В браузере закэширован старый `app.js`. Обновите со сбросом кэша: **Ctrl + Shift + R** (или Cmd + Shift + R). Сервер теперь отдаёт HTML/JS/CSS с `Cache-Control: no-store`, так что дальше это не повторится. |
| Надо понять, свежая ли версия | Вкладка «Настройки» → «О программе»: там номер сборки. Тот же штамп печатается на экранах сбоя. |
| Низ страницы обрезан, список не листается | Проверьте `npm run layout` — он замеряет прокрутку всех панелей в настоящем браузере. Причина такого класса ошибок всегда одна: контейнер растягивается под содержимое (грид-элемент с `min-height: auto` или флекс-элемент без `min-height: 0`), поэтому `overflow-y: auto` не включается. Лечится `minmax(0, 1fr)` у строки грида и `min-height: 0` у самих контейнеров. |
| В превью всё зависло после перезапуска сервера | Превью привязано к процессу: перезапуск даёт новую страницу предпросмотра, старая может остаться мёртвой. Откройте превью заново. |
| Проверить, что сломалось | Семь проверок: `npm test` — 40 модульных тестов логики, `npm run smoke` — 85 проверок интерфейса, `npm run layout` — прокрутка панелей, `npm run lyrics` — караоке в реальном времени, `npm run rec` — рандом и рекомендации на живых треках, `npm run themes` — контраст и смена тем, `npm run shots` — снимки тем. Всем, кроме `npm test`, нужен запущенный сервер. Красный тест покажет, что именно отвалилось. |
| Плохо видно на свету / хочется другой вид | Значок палитры у строки поиска или **T** — тема меняется сразу и запоминается. Светлые: «День» и «Бумага»; клавишу можно жать несколько раз, чтобы пролистать все шесть. |
| «Источник не ответил» и трек не играет | Так плеер сообщает, что конкретный сервис не отдал звук (бывает у отдельных радиостанций и «серых» CDN). Это локальная ошибка одного трека: сервер продолжает работать, остальные треки играют. Раньше такая ошибка могла уронить весь сервер — теперь не может, и это проверяется тестом `tests/server.test.mjs`. |
| После серии живых проверок компьютер «думает», тесты виснут | Браузерные проверки оставляли зависшие процессы Chrome: память кончалась, и следующие запуски висели без причины. Теперь каждый запуск убивает свою группу процессов, а перед проверкой инструменты подчищают забытые. Если что-то всё же осталось: `pkill -9 -f chrome-linux64`. |
| Текст не идёт в реальном времени: подсветка замирает, помогает только переоткрыть панель | Значит, оборвалась автоматика. Проверьте `npm run lyrics` — он слушает живой трек ~30 секунд и честно скажет, двигается ли подсветка сама. Подсветку двигают два независимых механизма: событие `timeupdate` у `<audio>` и тикер раз в 220 мс (он нужен для режима YouTube, где время приходит из IFrame-плеера). |
| Треки не играют, хотя находятся | У части сервисов только 30-секундные превью, а Яндекс.Музыка может требовать подписку Плюс. Смотрите таблицу источников во вкладке «Настройки». |

## ⚙️ Вкладка «Настройки»

Всё, что требует ключа или входа, убрано с глаз в отдельную вкладку — на главном экране
остались только навигация, список источников и индикатор сервера. В настройках:

- **Аккаунты и ключи** — Яндекс.Музыка (вход по коду / отключение) и YouTube (вставить или
  сменить API-ключ, видно остаток квоты на сегодня).
- **Источники музыки** — таблица по всем шести сервисам: что отдаёт (полный трек / превью /
  iframe), нужен ли вход, какие возможности подключены.
- **Тексты и караоке** — переключатель «открывать текст автоматически»; объяснение, откуда берутся тексты.
- **Вкусы и рекомендации** — автоподбор в конце очереди, учёт пропусков, состав вкусов, сброс истории.
- **Оформление** — галерея шести тем с образцами; применяется сразу и запоминается.
- **Данные** — экспорт и импорт избранного в JSON, очистка избранного и очереди.
- **Горячие клавиши** и **О программе** (состояние сервера).

Ключи и токены лежат только на вашей машине в файлах `.yandex-auth.json` / `.youtube-key.json`
и никуда, кроме API самих сервисов, не уходят.

## 🎤 Караоке и тексты

Кнопка с текстом в плеере (или клавиша **L**) открывает панель караоке:

- **синхронный текст с таймкодами** (формат LRC) подсвечивает текущую строку **в реальном времени**
  и сам подкручивает список; клик по строке — перемотка на это место трека.
  Подсветку двигают два независимых механизма: `timeupdate` от `<audio>` и тикер 220 мс —
  второй страхует режим YouTube, где время приходит из IFrame-плеера. Если панель закрыта,
  работа не выполняется: при открытии позиция сразу пересчитывается;
- если синхрона нет, показывается обычный текст без подсветки;
- строка над панелью честно говорит, что и откуда взялось: `lrclib · синхрон`.

Откуда берутся тексты (проверено вживую, сентябрь 2026):

| Источник | Статус | Почему |
|---|---|---|
| **LRCLIB** `lrclib.net` | ✅ основной | открытый API, **без ключа**, отдаёт готовый LRC с таймкодами |
| lyrics.ovh | ✅ резерв | простой текст без тайминга — годится как запасной вариант |
| Genius | ❌ | официальный API отдаёт только метаданные, страницы закрыты Cloudflare (403), неофициальный поиск — не JSON |
| Musixmatch | ❌ | платный ключ и ручное одобрение аккаунта |
| Яндекс.Музыка `/lyrics` | ❌ | требует подпись `timeStamp` + `sign`, из плеера недостижимо |

Серверная часть — `src/lyrics.js` и `GET /api/lyrics?title=&artist=&album=&duration=`:
кандидаты собираются из точного эндпоинта `/api/get` и поиска `/api/search`, ранжируются
(синхрон +10, простой текст +2, инструментал −8, штраф за расхождение длительности),
результат кэшируется на 24 часа. На реальной выборке из 138 треков синхрон нашёлся для
84 — и почти для всех настоящих песен (промахи приходились на радиостанции, ремиксы и каверы).

## 🔴 Что подключить нельзя

**Spotify.** В ноябре 2024 официально удалён `preview_url`
([анонс Spotify](https://developer.spotify.com/blog/2024-11-27-changes-to-the-web-api)) —
30-сек превью больше не отдаются. Web Playback SDK стримит, но требует **Premium
у каждого пользователя** и играет только на активном устройстве аккаунта. То есть Spotify
подключается максимум как **пульт** — управлять тем, что играет на телефоне или колонке.

**VK Музыка.** С 16 декабря 2016 года отключён публичный API для аудиозаписей: `audio.get`
и родственные методы возвращают `Access denied: no access to call this method`. Доступ
остался только официальным приложениям (фиксированный список `client_id`). Обходные пути
(парсинг `al_audio.php`, вытаскивание `client_secret`, selenium) нарушают ToS и ломаются от
любого обновления. Здесь VK нет — это сознательный отказ, а не недоделка.

## 🏗 Архитектура

```
Браузер  ──►  MuzPlayer server (:4173)  ──►  api.audius.co
  UI            • статика                    api.deezer.com
  <audio>       • /api/search   (веер)       itunes.apple.com
  <iframe YT>   • /api/stream   (Range)      radio-browser.info
  MediaSession  • /api/img      (whitelist)  api.music.yandex.net  ← node:https
  WebAudio      • /api/yandex/* (OAuth)      youtube.com/iframe_api
```

**Зачем сервер-прокси, а не чистый SPA:**

| Проблема | Как решает прокси |
|---|---|
| CORS у сторонних API | всё идёт с одного origin |
| Токены | живут на сервере, в браузер не попадают |
| Перемотка | проброс `Range` → `206 Partial Content` |
| Лимиты | TTL-кэш: квота YouTube не выгорает, чужие API не дёргаются |
| Картинки | прокси по whitelist хостов (защита от SSRF) |
| Смешанный контент | http-радиостанции не ломают https-страницу |
| Антибот Яндекса | нативный `node:https` вместо fetch |
| Отвалившийся источник | ошибка прокси остаётся локальной: `504 {error:'источник не ответил'}`, сервер продолжает работу |

**Единый интерфейс провайдера** (`src/providers/*.js`):

```js
export default {
  id: 'audius', name: 'Audius', accent: '#7c5cff',
  requiresAuth: false,
  capabilities: { search: true, trending: true, radio: false, stream: 'full' },
  async search(q, { limit }) { /* → Track[] */ },
  async trending({ limit, tag }) { /* → Track[] */ },
  async resolveStream(id) { /* → прямая ссылка на аудио */ },
};
```

`stream` бывает `full` (полный трек), `preview` (30 сек), `embed` (iframe) и `none`.
От этого значения зависят бейджи в интерфейсе и логика плеера.

Единая модель трека:

```js
{ uid, provider, id, title, artist, album, duration,
  artwork, playable, preview, live, embed, externalUrl, extra }
```

## ➕ Как добавить свой источник

1. Скопируйте `src/providers/itunes.js` в `src/providers/myservice.js`.
2. Реализуйте `search` и `resolveStream`.
3. Зарегистрируйте в `src/providers/index.js` (в `providers` и `order`).
4. Добавьте хосты обложек в `IMG_ALLOW` (`src/util.js`).
5. Перезапустите сервер — вкладка и строка в сайдбаре появятся сами.

## ⚖️ Юридическое

- Audius, Deezer, iTunes, Radio-Browser, YouTube — используются официальные публичные API.
- Яндекс.Музыка подключена через **неофициальный** API: это работает, но нарушает
  пользовательское соглашение и может сломаться в любой момент. Риск на пользователе.
- VK и Spotify-стриминг **сознательно не реализованы**: публичного доступа к звуку нет,
  а обход технических ограничений — нарушение ToS.
- Проект учебный. Для коммерческого продукта нужны лицензионные соглашения с правообладателями.
